طوطی آرا — بازطراحی فرانت‌اند فارسی و RTL
==========================================

اجرا
---
فایل‌ها را از ZIP خارج کنید و در همان پوشه یک static server اجرا کنید (بازکردن مستقیم file:// برای fetch تصویرهای گالری مناسب نیست). برای نمونه:
  python -m http.server 8000
سپس /index.html و /admin.html را باز کنید. hero.png کنار فایل‌ها باشد.

محتویات
-------
index.html: صفحه عمومی، پوستر و گالری
admin.html: پنل مدیریت واکنش‌گرا
styles.css: استایل‌های مشترک موبایل‌اول و RTL
site.js: دریافت گالری و فیلتر دسته‌بندی
admin.js: پیش‌نمایش محلی و نقاط اتصال قابل پیکربندی

گالری عمومی
------------
GET https://toti-ara-gallery.mohammadrezasamieizadeh.workers.dev/api/gallery
این GET موجود حفظ شده است. پاسخ JSON می‌تواند آرایه یا شیء شامل data/products/items باشد. هر ردیف باید image_url (یا imageUrl/image/url/photo_url) داشته باشد و می‌تواند name/title، category، price و description داشته باشد. مقدارهای category: sun، monk، green-cheek. اگر CORS، شبکه یا پاسخ HTTP خطا دهد، صفحه پیام خطا و دکمه تلاش دوباره نشان می‌دهد. قرارداد دقیق GET فعلی از منبع worker حاضر قابل تأیید نبود؛ پیاده‌سازی فرانت‌اند با شکل‌های بالا سازگار است.

ادغام امن پنل — نیاز سمت سرور
-----------------------------
مسیرهای ادمین عمداً خاموش هستند (ADMIN_API.enabled=false و routes خالی/null)؛ بنابراین UI موفقیت ساختگی نشان نمی‌دهد. در admin.js پس از پیاده‌سازی backend، مقدار enabled و baseUrl و مسیرها را تنظیم کنید. مسیرهای زیر قرارداد پیشنهادیِ لازم برای اتصال‌اند؛ هیچ‌کدام در Worker فعلی تأیید/اجرا نشده‌اند:
1. POST /api/admin/auth — ورودی JSON {"code":"..."} یا مکانیزم امن‌تر؛ خروجی {"token":"..."}. ترجیحاً کد/رمز هرگز در فرانت‌اند hard-code نشود؛ نشست امن و محدودسازی تلاش‌ها در سرور.
2. GET /api/admin/gallery — فهرست JSON از موارد با id,name,category,price,description,image_url.
3. POST /api/admin/upload — multipart/form-data با فیلد file؛ خروجی JSON خروجی JSON دارای فیلد url با آدرس تصویر بارگذاری‌شده. ذخیره پایدار فایل باید در سرویس سمت سرور/object storage باشد.
4. POST /api/admin/gallery — JSON {name,category,price,description,image_url}؛ پاسخ مورد ایجادشده.
5. DELETE /api/admin/gallery/{id} — حذف امن با احراز هویت؛ پاسخ 204 یا JSON.
تمام مسیرها باید توکن را بررسی کنند، اعتبار فایل/نوع/اندازه و مجوزها را سمت سرور کنترل کنند، CORS محدود داشته باشند و خطاهای HTTP استاندارد بدهند. در صورت تنظیم routes.delete روی مسیری شامل {id}، پنل دکمه حذف تأییدی را نمایش می‌دهد و درخواست DELETE را با Bearer token می‌فرستد. توکن در sessionStorage نگهداری می‌شود و باید backend آن را اعتبارسنجی کند.
