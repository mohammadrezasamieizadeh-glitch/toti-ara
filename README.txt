بستهٔ آرا، نسخهٔ V3

همهٔ فایل‌های این پوشه را مستقیماً در ریشهٔ مخزن GitHub Pages آپلود کنید، برای تکمیل deployment صبر کنید و سپس hard refresh یا پاک‌کردن cache را انجام دهید. سایت عادی را با index.html آزمایش کنید. برای عیب‌یابی آدرس را با ?supabase-test=1 باز کنید.

صفحهٔ عمومی فقط به hero.png موجود متکی است. گالری در صورت امکان آنلاین از Supabase می‌خواند و در خطای شبکه، پیام فارسی دوستانه و تماس را نشان می‌دهد. REST داخلی timeout ده‌ثانیه‌ای دارد و خطای خام شبکه به مشتری نمایش داده نمی‌شود.

اگر self-test نتواند به Supabase برسد، مشکل شبکه، DNS یا فیلترینگ است و با HTML ایستای GitHub Pages قابل تعمیر نیست. VPN یا شبکهٔ دیگر فقط یک آزمایش تشخیصی است و راه‌حل سایت محسوب نمی‌شود.

در supabase-config.js فقط کلید عمومی anon/publishable قرار دارد؛ service_role نباید در سایت عمومی باشد. برای پنل مدیریت، admin.html به دسترسی آنلاین Supabase و یکی از CDNهای SDK رسمی نیاز دارد و دکمهٔ تلاش دوباره دارد. اجرای supabase.sql برای ساخت جدول‌ها، RLS و bucket لازم است.
